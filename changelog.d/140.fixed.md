Moving a thread off `busy` after an orphan sweep, a stuck-thread release, or a settle retry no longer overwrites the status of a run another worker started on the thread in the meantime. The in-flight check and the status write are now one atomic store operation, `release_busy_thread`, added to `MetadataStoreProtocol` (custom metadata stores must implement it): a single statement on SQLite, a thread-row lock on Postgres, and a compare-and-set on a per-thread `version` on MongoDB, where creating a run reserves the thread until its run is inserted, so a release backs off from a run still being created. MongoDB keeps one narrow window, documented under orphaned runs in the threads-and-runs guide: a worker that stalls for a minute mid-creation and then dies can leave its never-executed run on a released thread, which the orphan sweep fails.
